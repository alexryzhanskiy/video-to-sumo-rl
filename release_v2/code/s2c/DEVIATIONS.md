# S2c: readings of the pre-registration and implementation details

Pre-registration v1 (frozen 29 Oct 2026), section 6, with section 1 (set-up), 4 (metrics), 5.1 (score) and the section 11 log (D9–D16). Where the text is silent or ambiguous, the most literal reading was taken. Written 29 Oct 2026 with the code `revision/s2c/s2c.py`, before any S2c tuning or evaluation run (only smoke tests on the laptop).

## Clarifications (the text is silent; no choice against the text)

| # | Topic | Reading implemented |
|---|---|---|
| C1 | Movements of a phase (6.2) | The movements listed for each phase in section 1: phase 0 = Svobody through [1,7], 1 = Svobody left [0,6], 2 = Prybuzka through [4,10], 3 = Prybuzka left [3,9] (RESCO's `phase_pairs`). Right turns are not movements of any phase there, so they are not in the pressure; their vehicles still count on the shared lane 0. Incoming lanes = the from-lanes of the movement's connections, outgoing lanes = their to-lanes (from `intersection.net.xml`; e.g. Svobody N through: `nN_nC_0`, `nN_nC_1` → `nC_nS_0`, `nC_nS_1`). "Vehicles" = all vehicles on the lane (`getLastStepVehicleNumber`), not only halting ones. |
| C2 | Forced change at the maximum green, free order (6.2) | **Clarified by the lead on 29 Oct 2026:** the change goes to the highest-pressure phase among the other three, the same rule as the DRL free-order designs (section 2, L1), regardless of h. Ties go to the phase that comes first in the field order after the current phase (from phase 2: 3, then 0, then 1). Field order: the next phase. |
| C3 | Timing of decisions and green limits | As the E13 DRL designs (RESCO `MultiSignal.step`, `legal_actions`): a decision every 5 s; a change = 3-s yellow, 4-s all-red only when the street changes, new green, next decision 2 s later. Change allowed when the green has lasted ≥ 12 s; forced when holding would pass 60 s by the next decision. Greens therefore last 12–57 s (D6), the first green of an episode 15–60 s. Smoke: free 12–57 s, field 12–60 s (the first green), 0 rule violations. |
| C4 | Threshold h | Switch if p(candidate) − p(current) ≥ h. With h = 0 equal pressures therefore switch. In free order the candidate is the highest-pressure other phase (ties as in C2). |
| C5 | Clearance states of MaxPressure | Generated exactly as RESCO's `create_yellows` (links green now and red/stop next turn yellow; the others keep their state) and the field program's all-red state, i.e. identical to the DRL designs. Verified: replaying two RESCO E13 smoke episodes (L2 IDQN-queue field order, L1 MPLight free order) with this code gives byte-identical tripinfo records. The Webster plans keep the field program's own states (its yellow keeps the right-turn link green), as the fixed plan. |
| C6 | Tuning episodes (6.2) | Evaluation protocol of section 4: 1800 s, arrivals by 1800 s, also at ×1.0 (E13 trains ×1.0 policies on 1500 s; tuning is an evaluation). Each of the 20 training files of a load runs with the five SUMO seeds 1042 + k + file index, k = 1..5, with the paired fixed-plan episode of the same file and seed (D11): 20 × 5 × (12 grid points + fixed) = 1300 episodes per load. |
| C7 | Deadlock rule when tuning at ×1.5 | Rule 5.1 ranks candidates "with any deadlock at ×1.0 or ×1.2" last. At ×1.5 no such episode exists, so the rule is not applied (literal reading); the deadlock counts are reported in `tuning_x15.csv`. Ranking otherwise `e13.rank` (score, then ties within 0.1 pp to the lower mean delay). |
| C8 | Which configuration runs on the scenarios | The ×1.0 configuration (tuned MaxPressure and Webster), as the ×1.0 models are evaluated on the scenarios (D12). Each load's configuration runs on its own load; no transfer runs. |
| C9 | Webster saturation flow per lane group (6.3) | Lane groups: through + right (lanes 0–1, shared lane) and left (lane 2) per approach. Through+right groups: 3600 / median saturated headway of `revision/runs/e8_validation/sim_discharge_headways.csv` (approach-level, measured in the through green, when only lanes 0–1 move). Left groups are not in the E8 file: measured with E8's own extraction and rules (same 15 runs, offset 16, cycles 2–12, first crossing ≤ 8 s, split at gaps > 8 s, saturated from position 4) in the left-turn window (12-s green + 3-s yellow = 15 s). The same code reproduces the E8 through values exactly (n and median for all four approaches). `plan/satflow.json`. |
| C10 | Webster flows | Counts of `sumo/turn_counts_edges.xml` summed over 0–1500 s, converted to veh/h (× 2.4) and multiplied by the load; right turns in the through group. |
| C11 | Webster with Y ≥ 1 (×1.5: Y = 1.10) | C0 is undefined; the cycle takes the upper bound, 150 s. |
| C12 | Webster greens | (C − L) y_i / Y, bounded to 12–60 s, then whole seconds by largest remainder (the total is kept, so the cycle stays at the bounded C; rounding each green would give 151 s). Since all flows scale with the load, y_i / Y is the same at every load, so the ×1.2 and ×1.5 plans are identical (both at C = 150 s). |
| C13 | Queue sampling (task item 3) | RESCO's definition replicated (vehicles on the 12 incoming lanes within 200 m whose RESCO waiting time is > 0: seen halting at an observation since entering these lanes). Verified: the replays in C5 give RESCO's `queue_lengths` exactly at all 336 + 292 decisions. Baselines are sampled on the fixed grid 5, 10, …, 1800 s, as asked; RESCO logs the learned controllers at their decision times (every 5 s, 9 s after a street change, to 1804–1808 s), so a comparison should use time averages or interpolation. |
| C14 | End of episode | MaxPressure and Webster use SUMO's `--end 1800`, as the fixed and actuated baselines (`baseline_job`). The RESCO DRL episodes end at the first decision at or after 1800 s (1800–1808 s); arrivals are counted by 1800 s in both. |
| C15 | B7 seeds and configuration | SUMO seed 42 + 1000 + k + e with k = 1 for the non-learning controllers and e = routeSampler seed mod 100 (7001…7005 → 1…5; the coming 7101…7110 → 1…10), as the spec suggests. MaxPressure uses the tuned configuration of the file's load (x10 → ×1.0, x12 → ×1.2). `e13/b7.py`: the final design's runs k = 1..5, same seeds with its own k. |
| C16 | Episodes run through libsumo | All S2c episodes (fixed and actuated included) run step by step through libsumo (TraCI if missing) to read the queue. Verified: fixed and actuated tripinfo records identical to E13's own baselines (`e13/runs_smoke/baselines`, va10 file 1, seed 1044); libsumo and TraCI give identical records for all six smoke episodes. |
